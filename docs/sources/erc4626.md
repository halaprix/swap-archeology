# ERC-4626 conversions

**ERC-4626 is a standard, not a venue.** There is no chain-wide vault enumeration. Discovery is per-issuer, and the only registry in this family is Aave's `StataTokenFactory 0xCb0b5cA20b6C5C02A9A3B2cE433650768eD2974F` (`getStataTokens()`, `getStataToken(address underlying)`). Ethena, sDAI and sUSDS are curated singletons.

## waEthWETH — resolved

`waEthWETH` is `0x0bfc9d54Fc184518A81162F8fB99c2eACa081202`, a `StataTokenV2` over the Aave v3 Ethereum **Core** market. Confirmed on chain: `asset()` = WETH, `aToken()` = `0x4d5F47FA6A74757f35C14fD3a6Ef8E3C9BC514E8`, and `StataTokenFactory.getStataToken(WETH)` returns exactly this address.

**Three different things share the "wrapped Aave WETH" idea and must never be merged:**

- `waEthWETH` `0x0bfc9d54…` — Core market, current factory
- `waEthLidoWETH` `0x0FE906e0…` — **Lido** market, same underlying WETH, different vault and different liquidity pool. Balancer's Aave-Lido boosted pools use this one.
- `0x252231882fb38481497f3c767469106297c8d93b` — what the **legacy** `StaticATokenFactory 0x411D79b8…` returns for WETH. A different token again.

A `waEthWETH/WETH` pool trades the wrapper against its underlying; it does not create an independent USDC exit.

## Quote semantics

Per vault, the reference is `previewRedeem` / `previewDeposit` **in the direction actually traded** — never `convertToAssets`, which EIP-4626 permits to ignore limits and rounding. `previewRedeem` floors; `previewMint`/`previewWithdraw` ceil.

At 25896003: sUSDe `previewRedeem(1e18)` = 1.246304373637716539, sDAI = 1.180071491613381287, sUSDS = 1.108317890335766516 (`chi` = 1108317394284368439953246243), waEthWETH ≈ 1.0699.

**`previewRedeem` is not an executability proof.** See sUSDe.

**`maxRedeem`/`maxWithdraw` are owner-scoped.** A zero-balance probe address returns 0 and says nothing about market capacity. Read the protocol-side cap instead: for waEth* Core that is `Pool.getVirtualUnderlyingBalance(WETH)` on `0x87870Bca3F3fD6335C3F4ce8392D69350B4fA4E2` (0x5c2d7aa72059d3a6fafa at 23549991, 0x432bda76e02f0e9ff8ec at 25896003). `maxRedeem` returns 0 outright if the Aave reserve is inactive or paused, and `StataTokenV2._update` carries `whenNotPaused`, so a paused stata token blocks transfers entirely.

sDAI and sUSDS redemptions draw from the Maker Pot / Sky Savings Rate rather than a vault ERC20 balance, so they are not bounded by `balanceOf`.

## sUSDe is not an atomic hop — at any pin

`StakedUSDeV2` guards `redeem()`/`withdraw()` with `ensureCooldownOff`. Whenever `cooldownDuration != 0` they **revert**.

| pin | `cooldownDuration()` |
|---|---|
| 23549991 | 604800 (7d) |
| 23550060 | 604800 |
| 23728292 | 604800 |
| 24356381 | 604800 |
| 25896003 | 86400 (24h) |

Verified directly: `eth_call redeem(0, addr, addr)` reverts `OperationNotAllowed` (selector `0xf50a3b52`) at **25896003** and at **21895170**, inside the sUSDe stress window. Meanwhile `previewRedeem(1e18)` happily returns 1.2463e18 and `maxRedeem(dummy)` returns 0. Neither says anything about executability.

The only vault exit is `cooldownShares`/`cooldownAssets` then `unstake` after the cooldown elapses — that spans blocks and cannot be a step in an atomic route. The record is therefore `unavailable`, so the router cannot silently price sUSDe at NAV. A market sale into a discovered pool (Ekubo USDe/sUSDe, Lista USDe pools, Curve) is a **different venue** and remains available.
